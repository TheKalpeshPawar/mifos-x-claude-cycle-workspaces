**Description:** Per-category monthly budget tracker persisting limits via kotlinx-serialization to DataStore. BudgetViewModel aggregates current-month AIS debits per category using kotlinx-datetime, computing used/limit fraction clamped to 1.0 and progress_color as error when over budget. Form validates amount is numeric and positive; duplicate category overwrites the existing limit. Users may delete a budget entry; deletion persists immediately to DataStore and refreshes the list.

### BudgetEntry Computed Fields

| Field | Computation | Notes |
|---|---|---|
| `used` | Sum of AIS debit amounts for this category in current calendar month from TransactionCache | kotlinx-datetime for month boundary |
| `limit` | Stored in DataStore | User-set value via form |
| `fraction` | `(used / limit).coerceIn(0.0, 1.0)` | Clamped to 1.0; drives progress_linear |
| `progress_color` | `if (fraction >= 1.0) error else primary` | Drives `budget_progress_bar.color` |
| `is_over_budget` | `fraction >= 1.0` | Drives `over_budget_alert` visibility |
| `remaining_label` | `if (used > limit) "£{used - limit} over" else "£{limit - used} left"` | Trailing text in budget_row_header |

## 7. API Dependencies

This screen is **client-only**: it makes no network calls. All data is read from and written to local device storage:

- **BudgetsDataStore** (`DataStore<Preferences>`) — persistence for BudgetEntry records (category + limit).
- **TransactionCache** — in-memory AIS debit cache used to compute the `used` amount per category for the current calendar month. This cache is populated by other AIS screens (e.g. transactions) and is read-only from the budgets screen's perspective.

No endpoints, no OBIE permissions, no bearer token required for this screen.
