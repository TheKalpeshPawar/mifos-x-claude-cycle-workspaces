## PUT /obp/v4.0.0/banks/{bank_id}/accounts/{account_id}/owner/standing-order/{standing_order_id}

**Auth:** DirectLogin (header: `DirectLogin token=<token>`)
**Tag:** Standing-Orders
**Trigger:** `OnSave` event — fires when user taps "Save Changes" and `validateForm()` passes

Updates the mutable fields (amount, frequency, start date, optional final date) of an existing standing order. Beneficiary name, IBAN, and currency are **immutable** after creation and must not be included in the request body.

### Path Parameters

| Name              | Type   | Description                                              |
|-------------------|--------|----------------------------------------------------------|
| bank_id           | String | OBP bank identifier (e.g., `rbs`)                       |
| account_id        | String | Source account ID from navigation params / ViewModel    |
| standing_order_id | String | Standing order ID from navigation params / ViewModel    |

### Request Body

```json
{
  "amount_value": "1200.00",
  "amount_currency": "GBP",
  "when": {
    "frequency": "MONTHLY",
    "start_date": "2026-01-01",
    "final_date": null
  }
}
```

### Request Fields

| Field                | Type    | Required | Description                                              |
|----------------------|---------|----------|----------------------------------------------------------|
| amount_value         | String  | Yes      | New payment amount, decimal string (e.g., "1200.00")     |
| amount_currency      | String  | Yes      | ISO 4217 currency code — must match account currency     |
| when.frequency       | String  | Yes      | DAILY / WEEKLY / MONTHLY / YEARLY                        |
| when.start_date      | String  | Yes      | ISO-8601 date (e.g., "2026-01-01")                       |
| when.final_date      | String? | No       | ISO-8601 date or null for indefinite                     |

### Response Fields

| Field          | Type    | Description                             |
|----------------|---------|-----------------------------------------|
| id             | String  | Standing order identifier               |
| amount_value   | String  | Updated amount                          |
| amount_currency| String  | Currency code                           |
| frequency      | String  | Updated frequency                       |
| start_date     | String  | Updated start date                      |
| final_date     | String? | Updated final date, null = Ongoing      |
| status         | String  | ACTIVE / PAUSED (unchanged by PUT)      |

### Error Codes

| Code | OBP Message                       | UI Error Displayed                                               |
|------|-----------------------------------|-----------------------------------------------------------------|
| 400  | INVALID_STANDING_ORDER_VALUES     | soe_error_banner: "Couldn't save your changes. Check the amount and try again." |
| 401  | USER_NOT_LOGGED_IN                | Navigate to login                                               |
| 403  | INSUFFICIENT_AUTHORISATION        | soe_error_banner: "Couldn't save your changes."                 |
| 404  | STANDING_ORDER_NOT_FOUND          | soe_error_banner: "Couldn't save your changes."                 |
| 409  | STANDING_ORDER_ALREADY_CANCELLED  | soe_error_banner: "This standing order has been cancelled and can no longer be edited." |

### Success Flow

On HTTP 200 the ViewModel emits `NavigateToDetail`. The UI:
1. Dismisses the saving spinner
2. Navigates back to standing-order-detail (pop)
3. standing-order-detail reloads from the server, reflecting the updated values

### Validation (Client-side, before API call)

| Field      | Rule                                  | Error Message                                  |
|------------|---------------------------------------|------------------------------------------------|
| amount     | Must be > 0.00                        | "Enter an amount greater than £0.00."          |
| startDate  | Must not be in the past               | "Start date can't be in the past."             |

Validation fires on `OnSave` before the PUT request is dispatched. Field-level errors surface as `amountError` and `startDateError` in the ViewModel state.
