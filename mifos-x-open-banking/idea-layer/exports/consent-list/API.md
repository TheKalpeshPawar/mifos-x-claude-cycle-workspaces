## GET /account-access-consents/{ConsentId}

Called **once per locally-stored ConsentId** at screen mount. In the HSBC sandbox a PSU can have at most one active consent; the screen shows all locally-known ConsentIds including Expired and Revoked entries for the History section. Results are partitioned client-side by the ViewModel into active and history lists.

### Path Parameters

| Param | Type | Source | Notes |
|-------|------|--------|-------|
| ConsentId | string | LocalConsentStorage | Stored locally after the consent-callback flow; one call per stored id |

### Response: OBReadConsentResponse1 (HTTP 200)

| Field | Type | Used for |
|-------|------|---------|
| Data.ConsentId | string | Route param when navigating to consent-detail |
| Data.Status | string | Partitioning into active vs history; chip colour mapping |
| Data.Permissions[] | string[] | Permission count summary (e.g. '11 data types shared') |
| Data.CreationDateTime | ISO-8601 datetime | `formatted_creation_date` shown on card |
| Data.ExpirationDateTime | ISO-8601 datetime | `days_until_expiry` + `expiry_color` + `formatted_expiry_date` computed by ViewModel |

### Client-Side Transforms (ViewModel — no extra API call)

| Transform | Logic |
|-----------|-------|
| active_consents | consents.filter { Data.Status == 'Authorised' } |
| history_consents | consents.filter { Data.Status ∈ [Expired, Revoked] } |
| days_until_expiry (per item) | ChronoUnit.DAYS.between(Clock.System.now(), Data.ExpirationDateTime).coerceAtLeast(0) |
| expiry_color (per item) | if (days_until_expiry ≤ 14) 'error' else 'on-surface-variant' |

| 500 | HSBC server error (ConsentStatusServerError) | Generic error state; retry available via retry_button |
| Network | IOException / timeout | Generic error state; retry available |

## Auth/Consent Notes

- The consent-status endpoint uses a **client_credentials** token — NOT the PSU bearer token. This allows the screen to read consent metadata even when the PSU session has expired.
- HTTP 401 is handled as a **distinct ui state** (`error_auth`) from all other errors. This prevents showing a misleading 'Retry' button when the underlying cause requires re-authentication via the FAPI OAuth flow.
- A **404** on a specific ConsentId means the consent no longer exists server-side. The ViewModel removes the stale id from LocalConsentStorage and proceeds with the remaining ids, rather than surfacing an error.
- The screen makes **multiple parallel requests** (one per stored ConsentId). All calls are dispatched concurrently; a single 401 promotes the entire screen to error_auth; a single non-401 failure promotes to the generic error state.
