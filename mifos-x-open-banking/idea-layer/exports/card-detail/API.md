## 1. Get Card Details

**GET** `/obp/v5.1.0/banks/{bankId}/cards/{cardId}`

Fetches full details for a specific card. This is the primary data source for this screen.

**Auth:** DirectLogin

**Path Parameters:**

| Param | Type | Description |
|---|---|---|
| bankId | String | OBP bank identifier (e.g., "gb.mifos") |
| cardId | String | Card unique identifier from the cards list |

**Response Fields:**

| Field | Type | Description |
|---|---|---|
| id | String | Card identifier |
| bank_id | String | Issuing bank identifier |
| bank_card_number | String | Masked PAN (e.g., "************4521") |
| name_on_card | String | Cardholder name (e.g., "Alex Johnson") |
| card_type | String | "debit" or "credit" |
| card_description | String | Display name (e.g., "Mifos Debit Visa") |
| card_network | String | "VISA" or "MASTERCARD" |
| allows | List\<String\> | Permitted operations |
| enabled | Boolean | false when frozen or deactivated |
| cancelled | Boolean | true when permanently cancelled |
| on_hot_list | Boolean | true when reported lost/stolen |
| technology | String | Card technology (e.g., "CHIP_AND_PIN") |
| expires | String | Expiry date (e.g., "2029-09") |
| replacement | CardReplacement | Replacement card details if applicable |

**Sample Response:**

```json
{
  "id": "card-4521-uuid",
  "bank_id": "gb.mifos",
  "bank_card_number": "************4521",
  "name_on_card": "Alex Johnson",
  "card_type": "debit",
  "card_description": "Mifos Debit Visa",
  "card_network": "VISA",
  "allows": ["credit", "debit", "cash"],
  "enabled": true,
  "cancelled": false,
  "on_hot_list": false,
  "technology": "CHIP_AND_PIN",
  "expires": "2029-09",
  "replacement": null
}
```

**Error Codes:**

| Code | Message | UI Behaviour |
|---|---|---|
| 400 | INVALID_CARD_ID | Show error state |
| 401 | USER_NOT_LOGGED_IN | Redirect to login |
| 403 | INSUFFICIENT_AUTHORISATION | Show error state |
| 404 | CARD_NOT_FOUND | Show error: "Unable to load card details" + retry |

## Biometric-Gated Card Reveal

The "Show card details" link triggers `BiometricAuthUseCase` locally. On biometric success, a bank-specific secure endpoint (not part of OBP standard) retrieves the full unmasked PAN and CVV. This is handled outside the standard OBP contract.

**Biometric flow:**

1. User taps "Show card details"
2. `BiometricAuthUseCase.authenticate()` → system biometric prompt
3. On `BiometricAuthSucceeded` → fetch unmasked card data from secure endpoint
4. Display: full PAN, CVV, expiry for 30 seconds, then re-mask automatically

## Card Freeze / Unfreeze

OBP does not have a dedicated freeze endpoint in v5.x standard. Freeze/unfreeze is implemented via:

- `toggle_card_status` action → bank extension or card management API
- The `enabled` field in GET response reflects current freeze state
- Visual: when `enabled: false`, the frozen state renders with grey overlay and "FROZEN" watermark

---

## Report Lost/Stolen

Reporting sets `on_hot_list: true` via a bank-specific extension. The `cancelled` field becomes `true` upon permanent cancellation. After reporting, the card is permanently blocked and a replacement card is typically issued (tracked via `replacement` field in the response).

**Error escalation path:** If `REPORT_FAILED` → surface phone number "0800 123 456" in error message for immediate human escalation.
