| Source | Notes |

## Computation Model

`PfmDashboardViewModel.loadFinancesOverview(period: PfmPeriod)` dispatches the following parallel coroutines (all in viewModelScope; no network calls):

| Coroutine | Inputs | Output |
|-----------|--------|--------|
| Balance sum | All account balances in cache | `netWorth` (GBP String) |
| Period aggregation | Transaction rows windowed by kotlinx-datetime `Clock.System.now()` − period | `periodIncome`, `periodSpend`, `netCashflow` |
| Category grouping | AIS debit rows, ranked by MerchantCategory total descending | `topCategories: List<PfmCategory>` with `percentage_of_spend` |
| Insight rules | category-up-vs-prior-period (>10% delta), savings-rate-positive (≥20%), category-down-positive | `insights: List<PfmInsight>` |

Period values: `7d` (PfmPeriod.DAYS_7) · `30d` (PfmPeriod.DAYS_30, default) · `3m` (PfmPeriod.MONTHS_3)

| `EmptyCacheError` (EC-PFM-001) | No transactions in local cache after account sync | `PfmDashboardUiState.Empty` — instructional empty state; no retry button; PSU should visit Transactions screen to populate cache |
