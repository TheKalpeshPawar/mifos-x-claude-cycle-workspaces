## POST /account-access-consents

OBIE consent-create. Authenticates with a `client_credentials` bearer token (not a PSU access token) obtained prior to redirect. Initiates the account-access consent that the PSU will subsequently authorise in HSBC.

| `Data.ExpirationDateTime` | ISO 8601 | now + 90 days |
| `Data.TransactionFromDateTime` | ISO 8601 | Start of transaction history window |

## FAPI 1.0 Advanced Handoff

This screen does not complete the OAuth flow. After a successful consent-create (HTTP 201), the ViewModel executes the following sequence before the screen transitions to `Authorising`:

1. `Data.ConsentId` extracted from `OBReadConsentResponse1` and stored in `LocalStorage` under key `consent-id-{state}`.
2. `FapiAuthBuilder` constructs a FAPI 1.0 Advanced `/authorize` URL with:
   - `response_type=code id_token`
   - `scope=openid accounts`
   - `request_object_alg=PS256` (signed with jose4j using private_key_jwt)
   - Parameters: `consentId`, `nonce`, `state`
3. `state` and `nonce` values stored in `LocalStorage` under `oauth-state-{state}` for callback validation.
4. `Navigator.launchAppToAppRedirect(authorizeUrl)` fires the OS intent to the HSBC mobile app.
5. Screen transitions to `ConsentOnboardingUiState.Authorising`.
6. The PSU completes SCA and account selection in the HSBC app, then returns via the TPP `redirect_uri` scheme registered in `AndroidManifest`. The OS routes the deep link to the `consent-callback` screen, which exchanges the authorisation code for a PSU access token.

No PSU-scoped token is present on this screen. The `consent-callback` screen owns the token exchange.
