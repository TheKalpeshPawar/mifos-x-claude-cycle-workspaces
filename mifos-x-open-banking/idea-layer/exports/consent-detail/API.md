## GET /account-access-consents/{ConsentId}

Retrieves the full `OBReadConsentResponse1` for the PSU's active consent. Authenticated with a **client_credentials** token. The ViewModel maps `Data.Permissions[]` to human-readable `PermissionDetail` labels via `PermissionsMapper` and computes `expiryWarningDays` from `Data.ExpirationDateTime`.

## DELETE /account-access-consents/{ConsentId}

Revokes the PSU's consent. Called only after the PSU confirms via the `revoke_confirm_dialog`. Authenticated with a **client_credentials** token. A `404` response is treated idempotently — the consent was already revoked on the bank side, so the ViewModel proceeds with local cleanup and navigation identically to a `204`.

### Path Parameters

| Param | Type | Notes |
|-------|------|-------|
| ConsentId | string | Same ConsentId used in the GET request |

### Response

| HTTP | Body | ViewModel Action |
|------|------|-----------------|
| 204 | No Content | Clears PSU access token + ConsentId from EncryptedSharedPreferences; navigates to consent-list |
| 404 | OBIE error object (optional) | Treated as idempotent already-revoked; same local cleanup + navigation; no error state shown |
| 5xx | OBIE error object | Transitions to error state (RevokeServerError) — PSU can retry |
| Network | — | Transitions to error state (NetworkError) — PSU can retry |

## Auth/Consent Notes

- Both endpoints use **client_credentials** token authentication — NOT the PSU bearer token obtained during the consent-callback flow. This allows the app to read and revoke consent metadata independently of whether the PSU's session token is still valid.
- The PSU access token and ConsentId are stored in **EncryptedSharedPreferences** (Android) and must be cleared after a successful or idempotent revocation.
- The two-step revoke UI (confirm dialog → DELETE) is a ViewModel-enforced UX gate. The DELETE endpoint is not called until `executeRevoke` is dispatched from `dialog_confirm_button`.
- `404` on DELETE is treated as a success path (idempotent revoke) per the OBIE AIS v4.0 spec, which allows the server to have already processed a prior revocation for the same ConsentId.
