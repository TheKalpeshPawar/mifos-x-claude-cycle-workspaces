## Overview

Account Detail makes **2 parallel** server calls on screen mount. Both require a valid FAPI 1.0 bearer token and an active AIS consent with the specified permissions.

| Call | Method | Path | Permission | Parallel? |
|---|---|---|---|---|
| Account metadata | GET | `/accounts/{AccountId}` | ReadAccountsDetail | Yes (async) |
| Account balances | GET | `/accounts/{AccountId}/balances` | ReadBalances | Yes (async) |

## Endpoint 1 — Account Metadata

```
GET /accounts/{AccountId}

Auth:      Bearer {access_token}   (FAPI 1.0 Advanced — mTLS + signed request)
Accept:    application/json
```

### Error Handling

|---|---|---|---|

### Response Fields Used by UI

| Field path | UI component | Notes |
|---|---|---|
| `Data.Balance[*].Type` | `balance_row` supporting text | OBIE type enum: InterimAvailable, InterimBooked, OpeningBooked, etc. |
| `Data.Balance[*].Amount.Amount` | `balance_row` trailing (titleMedium) | Signed decimal string |
| `Data.Balance[*].Amount.Currency` | `balance_row` trailing (titleMedium) | e.g. `GBP` |

**State routing from balances response:**  
- `Data.Balance` non-empty → `AccountDetailUiState.Content`  
- `Data.Balance` empty → `AccountDetailUiState.Empty` (zero-balance account, e.g. Global Wallet)

### Error Handling

Same error types as Endpoint 1 (both calls share the same error sealed class). If either parallel call fails, the ViewModel emits an `Error` state with the relevant type and recoverability flag.

## Parallelism Contract

```kotlin
coroutineScope {
    val accountDeferred = async { accountDetailRepository.getAccount(accountId) }
    val balancesDeferred = async { accountDetailRepository.getBalances(accountId) }
    val account = accountDeferred.await()
    val balances = balancesDeferred.await()
    // → emit Content or Empty based on balances.isEmpty()
}
```

Total latency = `max(getAccount, getBalances)` rather than sum.
