## POST /obp/v5.0.0/users/password-reset

**Auth:** None (unauthenticated endpoint)
**Tag:** Auth
**Trigger:** `onSubmitClicked()` — user taps "Send Reset Link" button

This endpoint requests a password reset link be sent to the user's registered email address. The response is intentionally non-enumerable — it returns the same success message whether or not the identifier maps to a real account, preventing account enumeration attacks.

### Request Body

| Field    | Type    | Required | Description                                                                      |
|----------|---------|----------|----------------------------------------------------------------------------------|
| username | String? | no*      | OBP username of the account. Required if email is omitted.                       |
| email    | String? | no*      | Email address associated with the account. Required if username is omitted.      |

\* At least one of `username` or `email` must be provided. The `fpw_identifier_input` field accepts either format and the ViewModel routes to the appropriate field based on input pattern (`@` present → email, else username).

### Sample Request

```json
{
  "email": "john.doe@example.com"
}
```

or

```json
{
  "username": "john.doe"
}
```

### Response Fields

| Field   | Type   | Description                                                                 |
|---------|--------|-----------------------------------------------------------------------------|
| message | String | Human-readable confirmation e.g. "Reset link sent to registered email."     |

### Success Handling

On HTTP 200: transition `uiState` to `success`, hide form section, show success section (mark_email_read icon + "Check your inbox" + non-enumeration copy).

### Error Codes

| Code | OBP Message                      | UI Handling                                                          |
|------|----------------------------------|----------------------------------------------------------------------|
| 400  | INVALID_REQUEST / missing fields | Show error banner: "We couldn't find an account with that username or email." |
| 404  | USER_NOT_FOUND                   | Show error banner (same message — do not reveal account non-existence)|
| 429  | RATE_LIMITED                     | Show error banner: "Too many attempts. Please wait a few minutes."   |
| 500  | Server error                     | Show error banner: "Something went wrong. Please try again."         |

### Security Notes

- Error messages for 404 and 400 must be identical in the UI — account enumeration prevention.
- The `fpw_success_body` copy ("If an account exists...") applies regardless of whether the server returned a real match.
- No token or session required for this endpoint.
