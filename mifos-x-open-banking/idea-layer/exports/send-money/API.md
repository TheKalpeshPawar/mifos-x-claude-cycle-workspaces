# API Reference — Send Money

| Field    | Value                                  |
|----------|----------------------------------------|
| Feature  | send-money                             |
| Base URL | https://apisandbox.openbankproject.com |

> Contract verified against live OBP sandbox 2026-06-04 (bank `ac.bank.uk`, account `ac.checking.001`, view `owner`). The hub lists beneficiaries; the actual transfer runs on `send-money-confirm` via the **COUNTERPARTY** transaction-request.

---

## GET /obp/v4.0.0/banks/{bankId}/accounts/{accountId}/{viewId}/counterparties

**Auth:** DirectLogin · **Tag:** Counterparties · viewId = `owner`.
Beneficiary list for the hub. Fields: `counterparty_id`, `name`, `other_account_routing_scheme`, `other_account_routing_address`, `other_bank_routing_scheme`, `other_bank_routing_address`, `is_beneficiary`. Errors: 401 OBP-20001, 404 OBP-30018.

## GET /obp/v4.0.0/banks/{bankId}

**Auth:** DirectLogin · **Tag:** Bank. Resolves `other_bank_routing_address` (OBP scheme) → `full_name` for the beneficiary subtitle. Cached.

## GET /obp/v3.0.0/my/banks/{bankId}/accounts/{accountId}/transactions

**Auth:** DirectLogin · **Tag:** Transaction. Used to order "Recent Recipients" by latest payment (join `details.description` ↔ counterparty `name`).

---

## POST /obp/v4.0.0/banks/{bankId}/accounts/{accountId}/{viewId}/transaction-request-types/COUNTERPARTY/transaction-requests

**Auth:** DirectLogin · **Tag:** TransactionRequests · viewId = `owner`.
**Executes the payment** (Confirm & Send on `send-money-confirm`). Pays a registered counterparty by id — works for any beneficiary regardless of routing scheme.

### Request body

```json
{
  "to": { "counterparty_id": "b7b0394c-f1d1-40a9-8ec1-920b8d39f49c" },
  "value": { "currency": "EUR", "amount": "10.00" },
  "description": "Rent",
  "charge_policy": "SHARED"
}
```

> The payment `currency` must equal the from-account currency (else OBP-40003).

### Response (201)

`{ id, type:"COUNTERPARTY", status:"COMPLETED", transaction_ids:[...], charge:{ summary, value:{currency,amount} }, start_date }`

### Error Codes

| Code | Message | UI Handling |
|------|---------|-------------|
| 400  | OBP-10001: Incorrect json format | Generic failure |
| 401  | OBP-20001: User not logged in | Re-authenticate |
| 422  | OBP-40008: Can't send a payment with a value of 0 or less | "Enter a valid amount" |
| 422  | INSUFFICIENT_FUNDS | "Insufficient funds in your account." |
| 423  | DAILY_LIMIT_EXCEEDED | "This payment exceeds your daily transfer limit." |

> Note: the plain SEPA transaction-request (`.../SEPA/...` with `to:{iban}`) also returns 201 but only for IBAN-scheme counterparties; COUNTERPARTY is the universal path used by the app.
