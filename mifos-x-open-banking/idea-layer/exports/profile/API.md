## GET /accounts/{AccountId}/party

Retrieves the PSU identity record (name, email, mobile, postal address) for the specified account.
The response is merged with the locally cached consent record to produce the profile screen's combined `ProfileState`.

### Path Parameters

| Param | Type | Required | Description |
|-------|------|----------|-------------|
| `AccountId` | String | Yes | OBIE account identifier (from accounts list) |

### Request Headers

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer <access_token>` |
| `x-fapi-financial-id` | ASPSP financial ID (set by Ktorfit interceptor) |
| `Accept` | `application/json` |

### Response: OBReadParty2 (HTTP 200)

| Field | Type | Description |

## 401 Token-Refresh Sequence

1. ProfileViewModel dispatches `loadProfile()`.
2. GET /accounts/{AccountId}/party returns HTTP 401 (access token expired).
3. `TokenRepository.refreshToken()` is called.
4. If refresh succeeds: retry GET /accounts/{AccountId}/party once with new token.
5. If refresh returns second HTTP 401 (refresh token also expired): `executeSignOut()` is called, clearing all tokens and ConsentId from EncryptedSharedPreferences / Keychain, and navigating to the login screen.
6. The PSU must re-initiate the full FAPI consent-and-authorisation flow from login.

---

## Permission Gating

`ReadParty` must be present in the PSU's active Open Banking consent.

- HTTP 403 → ViewModel emits `Error("Consent does not include profile access. The ReadParty permission was not granted when you authorised this app.")`.
- The 403 error message explicitly names the missing permission (CC5 capability-completeness gate).
- No Re-authorise CTA on the error state; the PSU manages consent permissions via the consent-detail screen (accessible from the profile content state via Manage Consent button).
