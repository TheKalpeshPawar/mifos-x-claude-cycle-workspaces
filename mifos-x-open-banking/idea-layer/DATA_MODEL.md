**This project owns no database and defines no schema.** Every entity below is an **OBIE wire
type** returned by HSBC. The "data model" is a set of client contracts, not tables — there is no
`tables[]` and no `persistence_contract` anywhere in the 23 `data-flow.yaml` files.

**`AccountId` is the join key for every AIS resource.** That is why nine features depend on
`accounts` and why every account-scoped store keys on it.

**The two consents are separate and must not be conflated.** The AIS consent governs data reading
and its tokens live in `ConsentSession`. The PIS consent governs **one payment** and its token is
deliberately **never written to `ConsentSession`** — doing so would overwrite the data-sharing
session with a single-payment authorisation.

## Entity Details

### `OBActiveOrHistoricCurrencyAndAmount` — the money primitive

`{ Amount: String, Currency: String }`. Amount is a **string**, not a number, and is held and
validated as **minor units** through `core/common/FormatMoney`. Formatting happens in the
ViewModel; composables receive finished label strings.

### `OBCashBalance3` — and the `balanceIsCredit` trap

Carries `CreditDebitIndicator`, `Type` (e.g. `ITBD`) and `Amount`. On a **transaction's** embedded
balance, HSBC sets the indicator to the *transaction's* direction, not the balance's — the sandbox
returns `Balance {Debit, ITBD, 21530.92}` for an account whose `/balances` reports
`{Credit, ITBD, 21530.92}`. Signing a running balance off it rendered £21,530.92 as −£21,530.92.
Running balances are therefore displayed **unsigned**.

### `OBAccount6` — no `AccountSubType` in v4.0

HSBC UK Personal AIS v4.0 replaced the OBIE v3 `AccountType`/`AccountSubType` pair with
`AccountCategory` + `AccountTypeCode` (`CHAR, CARD, CACC, LOAN, MORT, SVGS`) — **no wallet code**.
`AccountMapper` resolves
`accountSubType = accountSubType ?: accountTypeCode ?: accountCategory ?: description ?: ""`, and
every screen normalises through `canonicalSubtype()`, which accepts both the OBIE enum names and
the ISO codes. A Global Money wallet reports `CACC`, indistinguishable from a current account —
which is why the free-text `Description` is often the only field naming the product.

### `OBReadConsentResponse1` — 90-day lifecycle

`Permissions[]` is the full grant list, rendered untruncated at three surfaces (login, consent
list, consent detail). Expiry is a regulatory fact — SCA-RTS Art 36(6) / Art 10A.

### `OBWriteDomesticConsent4` — the consumer `Risk` shape

`Risk` is a **required member** of the request envelope, but `OBRisk1` declares **no required
properties** — so `Risk: {}` is legal and merchant fields are omittable. This project sends
`PaymentContextCode: TransferToThirdParty` (or `TransferToSelf`) and **no** `MerchantCategoryCode`,
`MerchantCustomerIdentification` or `DeliveryAddress`. HSBC's own Postman examples use the merchant
shape; copying them verbatim models the wrong application.

`OBDomestic2` requires only `InstructionIdentification`, `EndToEndIdentification`,
`InstructedAmount` and `CreditorAccount` — `DebtorAccount` is optional.

## Persistence

| Store | Backing | Count |
|---|---|---|
| `createStore(fetcher, sourceOfTruth, validator)` | **Room** | 2 — `accountsStore`, `transactionsStore` |
| `createMemoryStore(fetcher)` | memory | 13 |
| Secure `Settings` | PSU tokens, consent meta | — |
| DataStore | theme preference | — |

The two Room-backed stores must call `validator.markFresh()` in the fetcher or the TTL never
starts, and their source-of-truth reader emits **`null` for empty** so a cold start renders Loading
rather than Empty.
