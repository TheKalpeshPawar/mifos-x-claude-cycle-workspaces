## Overview

A Kotlin Multiplatform client for the UK Open Banking (OBIE) standard, targeting the HSBC UK
Personal sandbox. It reads account information as an **AISP** and, since the 2026-07-30 scope
reversal, initiates domestic single payments as a **PISP**.

## Source of Truth & Data Ownership

**This project owns no backend and no database.** It is a pure client of the HSBC Open Banking REST
API. Two consequences shape everything below:

1. **`server-layer/` holds *client contracts*, not schema.** The Ktorfit interfaces and OpenAPI
   specs under `idea-layer/server/` describe an API someone else operates. `backend.owned: false`
   in `PROJECT_CONFIG.yaml`, so owned-DB coherence checks correctly skip this project.
2. **There are no owned tables.** No `tables[]` and no `persistence_contract` appears anywhere in
   the 23 `data-flow.yaml` files. Persistence is limited to Store5 caches (memory, and Room for
   two stores) plus secure `Settings` for PSU tokens and DataStore for preferences.

| Data | Owner | Lifetime |
|---|---|---|
| Accounts, balances, transactions, statements, payees, mandates | **HSBC** | fetched per consent |
| PSU access + refresh tokens | secure `Settings` (`SettingsConsentSession`) | until `forgetAll()` |
| Theme preference | DataStore (`UserDataRepository`) | until cleared |
| Store5 caches | memory (13 stores) · Room (2 stores) | until `clearAll()` |

**`ConsentSession.isActive()` is the source of truth for "signed in"** — not the DataStore
`UserData`. Tokens live in secure `Settings`, so `clearUserData()` alone cannot sign a user out.

## Architecture Style

**Stream-first MVI.** A ViewModel extends `BaseViewModel<State, Event, Action>`, funnels every
input through `handleAction`, and the UI collects `stateFlow`.

**The repository is a stateless gateway.** Given an id and a `CoroutineScope` it calls
`asScreenStream(...)` and returns a `ScreenDataStream<T>`; **the ViewModel owns that stream** and
Retry calls `stream.refresh()` — never `repository.refresh()`. Repositories are Koin `single`s
(process-scoped), so per-screen state inside one is a bug.

Two documented exceptions, not to be copied: `AccountsOverviewRepository` (holds stream state) and
`ProductRepository` (storeless one-shot `suspend`, because product terms must never be served from
cache).

**Screen state** is the shared `ScreenState<T>` from `core-base` — `Loading / Empty / NoNetwork /
Unauthenticated / Error / Content<T>` — mapped in the ViewModel to a feature-owned `<F>UiState`
sealed interface. Error taxonomies are **per-feature**, not shared.

`trySendAction` only enqueues onto a channel drained in `viewModelScope`; nothing has run when it
returns.

## Layered Structure

Enabled: `idea · design-spec · server · client · feature · infrastructure · platform · testing ·
release`. None disabled.

```
core-base/*      imported kmp-project-template framework — OFF-LIMITS, consume only
core/*           app-shared: data · store · network · model · ui · common · designsystem
feature/*        18 vertical slices, one per screen
cmp-*            platform entry points + cmp-navigation (NavHost, tabs, registration)
```

| Layer | Rationale (from `§layers.layer_rationale`) |
|---|---|
| `server` | Holds **client contracts** for the external HSBC AIS API (Ktorfit interfaces) — no owned DB |
| `platform` | `expect`/`actual` for mTLS, secure storage, and app-to-app redirect handling |

**Dependency direction is strictly downward:** `feature/*` → `core/*` → `core-base/*`. A feature
never reaches another feature; shared UI goes to `core/ui`, shared logic to `core/common`.

`core-base/*` has been modified exactly once in the project's history (`ScreenDataStream`'s
constructor made public, commit `c27c10a`). Treat it as read-only.

## Security Architecture

FAPI 1.0 Advanced, and the parts that constrain the client:

| Mechanism | Applies to | Note |
|---|---|---|
| mTLS (QWAC transport cert) | all calls | platform-specific TLS config via `expect`/`actual` |
| DCR (signed SSA) | onboarding | `POST /register` |
| `private_key_jwt` (PS256) | token endpoint | `BuildClientAssertion.kt#signPs256` |
| OAuth2 + PKCE S256, signed request object | authorize | app-to-app; PSU authenticates at HSBC |
| **Detached JWS** (`x-jws-signature`, PS256, `b64:false` + `crit`) | **PIS writes only** | absent → HSBC returns `400 U019` |
| `x-idempotency-key` | **PIS writes only** | must persist across retries |

**Two hosts, and confusing them fails in a misleading way.** The mTLS resource host is
`secure.sandbox.ob.hsbc.co.uk`; the front-channel authorize host is `sandbox.ob.hsbc.co.uk`. A
request sent to the authorize host fails looking like an auth fault rather than a wrong-host fault —
which is exactly how `api_manifest.yaml` carried the wrong base URLs unnoticed until 2026-07-30.
