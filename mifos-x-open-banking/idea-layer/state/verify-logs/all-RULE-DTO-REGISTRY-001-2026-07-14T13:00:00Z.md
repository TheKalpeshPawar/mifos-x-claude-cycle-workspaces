### D5-USED-BY-FRESH — WARN (systematic convention mismatch)

**Severity:** WARN (auto-fixable)
**Error code:** `DTO_USED_BY_DRIFT`

The `used_by[].feature` values across DTO files use **camelCase** identifiers (e.g., `accountDetail`, `consentCallback`, `atmLocator`) while the actual screen directory names — and therefore the authoritative feature IDs — are **kebab-case** (e.g., `account-detail`, `consent-callback`, `atm-locator`).

| DTO | used_by[].feature (stored) | Actual feature ID | Matches? |
|---|---|---|---|
| OBReadAccount6 | accountDetail | account-detail | NO (casing) |
| OAuthTokenResponse | consentCallback | consent-callback | NO (casing) |
| AtmDisplayItem | atmLocator | atm-locator | NO (casing) |
| OBReadConsentResponse1 | consentCallback, consentList, consentDetail | consent-callback, consent-list, consent-detail | NO (casing) |
| OBCashAccount3 | accountDetail, standingOrders, scheduledPayments, transactionDetail | account-detail, standing-orders, scheduled-payments, transaction-detail | NO (casing) |

This is a **project-wide systematic issue** affecting all DTOs whose consumers have hyphenated names. The camelCase form appears to have been generated by `/idea generate-dtos` mapping kebab-case directories to camelCase Kotlin identifiers.

**Fix:** Run `/idea generate-dtos --refresh-back-refs` to regenerate all `used_by[]` entries from authoritative consumer api.yaml files using consistent ID format.
